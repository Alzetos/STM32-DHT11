# DHT11 + ADC + TFT на EasyMx PRO v7 / STM32F107VCT7

Подробное объяснение программы: [CODE_EXPLANATION_RU.md](CODE_EXPLANATION_RU.md).

Проект STM32CubeMX 6.18.1, STM32Cube FW_F1 V1.8.7 и ARM GCC. Дисплей: установленный на EasyMx модуль Multi-Inno MI0283QT-8, 320×240, контроллер **ILI9341**. Программа использует интерфейс EasyMx CN32 / PORTE, 8080 8 бит, RGB565 (65 536 цветов). Надпись 262K на экране описывает возможности панели; для показаний используется режим RGB565. Сенсорный экран пока не используется.

Сборка проверяется двумя способами: штатный Makefile и STM32Make.make расширения STM32 for VSCode. Работа TFT и датчика на физической плате ещё не подтверждена; запись текущей версии в плату не выполнялась автоматически.

~~~sh

~~~

Артефакты этой сборки: build/debug/DHT11Monitor.elf, .hex, .bin. Настройки исправлены также для Attach STM32. Альтернативный профиль DHT11Monitor: ST-LINK USB (SWD) использует Build STM32 и build/DHT11Monitor.elf. Не смешивать ELF-файлы разных способов сборки.

## Светодиод PB6: порог и яркость по потенциометру

Для этих функций используется свободный штатный светодиод **PB6**, активный HIGH, аппаратный выход **TIM4_CH1**. TFT на PORTE, датчик PB8 и TIM2 не затронуты.

Используется **встроенный потенциометр P1 (10 кОм)** в секции ADC INPUT. При выключенном питании поставить **одну перемычку J8 в положение PA4**: движок P1 соединяется с PA4 / ADC1_IN4 через штатную цепь платы. Внешние провода потенциометра больше не нужны. PA0 освобождён. Включить группу штатных LED **PORTB 0–7 / PORTB_L**, отключить от PB6 конфликтующие I²C/EEPROM, установить внешние подтяжки PB6 и PA4 в нейтральное положение. Не нажимать кнопку PB6: вывод управляется таймером. Если нужен внешний LED: PB6 → резистор 330 Ом → анод LED, катод → GND; штатный LED уже имеет ограничение тока. На PA4 не подавать 5 В. Одновременно с движком потенциометра не подключать к PA4 другой активный источник.

На MCU-карте фактическое VREF+ зависит от её коммутации; руководство EasyMx также описывает опорное питание 1,8 В. Макрос ADC_VREF_MV пока сохранён равным 3300: для верных вольтов измерить VREF+ относительно VSSA и при 1,8 В задать 1800. Это меняет только отображение напряжения, не код АЦП и не порог 2048. Программа не растягивает показания P1 искусственно до 4095.

В текущей конфигурации выбран **DIVIDER_DIRECT**: U IN и U ADC показывают одинаковое напряжение движка P1. Профили фиксированного делителя сохранены и выбираются отдельно, когда подключён соответствующий делитель. Управление светодиодом сравнивает именно код АЦП, независимо от выбранного коэффициента напряжения.

В App/Inc/monitor_config.h выбрать режим и пересобрать:

~~~c
#define LED_CONTROL_MODE LED_MODE_PWM        // По умолчанию: порог + яркость
// Или LED_MODE_THRESHOLD: только выключен / включён
~~~

| Код АЦП | LED_MODE_THRESHOLD | LED_MODE_PWM |
|---:|---:|---:|
| 0…2047 | Выключен | Выключен |
| 2048 | 100% | 1% |
| 3072 | 100% | 50,5% |
| 4095 | 100% | 100% |

Режимы работают на одном светодиоде. В ШИМ-режиме положительная минимальная яркость 1% при 2048 нужна, чтобы условие «>=2048 — включён» выполнялось и на самом пороге. Далее коэффициент заполнения линейно растёт до 100%. Видимая яркость не обязана восприниматься глазом линейно. Гистерезис не добавлен: сравнение строго с 2048, поэтому при шуме рядом с границей возможны переключения.

TIM4 получает 72 МГц; Prescaler=71, Period=999:

~~~text
f_PWM = 72 000 000 / (71+1) / (999+1) = 1000 Гц
CCR1=0    → постоянно LOW → выключен
CCR1=10   → 1% заполнения
CCR1=1000 → постоянно HIGH → 100%
~~~

Канал — PWM mode 1, polarity HIGH. Импульсы создаёт таймер аппаратно, без прерываний. Настройки записаны в DHT11Monitor.ioc и реализованы в main.c / stm32f1xx_hal_msp.c. CubeMX из текущей среды не получил доступ к X11, поэтому автоматическая регенерация этой правки не проверена; соответствующий HAL-код обновлён вручную. Для сборки и запуска регенерация не требуется.

АЦП усредняет 16 отсчётов каждые **20 мс**; LED обновляется сразу после измерения. TFT обновляет показания не чаще раза в 250 мс и в строке 8 показывает LED PWM или LED SW и процент заполнения. Из-за блокирующего чтения DHT11 интервал обновления управления иногда увеличивается; сама генерация ШИМ продолжается аппаратно. При ошибке АЦП LED выключается. До первого измерения, включая прогрев датчика, LED выключен.

Функции в App/Src/led_control.c:

- LedControl_Init — запуск PWM с нулевой яркостью.
- LedControl_CalculateDuty — расчёт заполнения по коду АЦП и режиму.
- LedControl_Update — применение результата; при adc_valid=0 выключает LED.
- LedControl_SetMode — смена режима с выключением до следующего измерения.
- LedControl_GetMode / LedControl_GetDutyPermille — состояние для вывода на TFT.

Проверка логики без платы:

~~~sh
python3 tests/run_led_tests.py
~~~

Проверяются все 4096 кодов, точная граница 2047/2048, монотонность и пределы PWM, переключение режимов и отключение при ошибках. Это модель таймера, физическая яркость/частота проверяются на плате. После сборки прошить через профиль ST-LINK в VS Code. Поворачивать потенциометр и наблюдать ADC и LED на TFT, а также штатный индикатор PB6.

## Диагностика DHT11: NO RESPONSE

В строке 4 TFT теперь выводится уточнение BUS. В отладчике можно посмотреть структуру через DHT11_GetDiagnostics(): исходный уровень idle_high, этап stage, число bits_received, длительности ответа response_low_us/response_high_us и пять принятых байтов bytes.

| Строка TFT | Что установила программа | Что проверять |
|---|---|---|
| BUS: IDLE LOW | PB8 в покое читается как 0 | Питание, GND, перепутанные контакты, подтяжка вниз, LED-нагрузка PORTB_H, тачскрин DRIVEA, подтяжка DATA |
| BUS: RELEASE LOW | После стартового LOW линия не поднялась за 20 мкс | Нагрузка/замыкание DATA, слабая или отсутствующая подтяжка |
| BUS: NO REPLY | Линия поднялась, но начало ответа не обнаружено | Провод S/DATA к PB8, питание модуля, соответствие загруженной прошивки, неисправность датчика |
| BUS: RESPONSE LOW/HIGH | Начало обмена обнаружено, но ответный участок не прошёл проверку | Помехи, нагрузка, неправильные уровни, тайминг |
| BUS: BIT LOW/HIGH | Обрыв приёма битов | Контакты, длина проводов, помехи, остановки отладчика |
| BUS: BAD CHECKSUM | Принятые байты не сошлись по сумме | Уровни, проводка, тайминг |
| BUS: BAD DATA | Пакет не прошёл проверки полей | Тип/версия датчика, ошибки данных |
| BUS: OK | Пакет успешно принят | Дополнительных действий не требуется |

Это признаки этапа сбоя, а не однозначное установление неисправного компонента. В частности, IDLE LOW не доказывает поломку датчика.

Для текущего PB8 сначала отключить группу LED PB8–PB15 / PORTB_H, внешнюю подтяжку вниз и коммутацию тачскрина DRIVEA → PB8. PORTB 0–7 оставить включённой для PWM LED PB6. Положение PORTB/H VCC в блоке уровня кнопок задаёт сигнал при нажатии кнопок и не заменяет подключение провода питания модуля к VCC.

Мультиметром проверить VCC модуля относительно его GND и DATA/PB8 относительно GND. При питании/подтяжке 3,3 В DATA в покое должна быть близка к 3,3 В. Короткие импульсы обмена обычным мультиметром надёжно не измерить. Не подключать DATA с подтяжкой к 5 В без проверки допустимых уровней и согласования.

Перед проверкой снять breakpoints внутри DHT11_Read, нажать Continue и дождаться очередного опроса. Подключать по маркировке S/VCC/GND конкретного модуля, не по цвету проводов. Стандартная подтяжка для коротких проводов — около 4,7 кОм; у модуля она может уже быть установлена.

В драйвере также добавлено ожидание фактического подъёма DATA после отпускания Open Drain. Ранее задержка фронта из-за нагрузки могла быть ошибочно принята за низкую часть ответа. Это улучшение не устраняет замыкания, неверную распиновку или недостаточное питание.

Модельная проверка драйвера: python3 tests/run_dht_tests.py. Проверены правильный пакет, переполнение TIM2, задержка подъёма линии, зависшие уровни и каждый этап тайм-аутов. Работа на физическом датчике пока не подтверждена.

## Практическое подключение DHT11 через TS1 и проверка P1

TS1 на EasyMx PRO v7 предназначен для DS1820. У него есть GND, DQ и питание 3,3 В. Это не означает, что трёхконтактный модуль DHT11 можно вставить туда в том же порядке: у разных модулей порядок VCC/GND/S различается. Ориентироваться по маркировке платы модуля, не по его внешней форме. На выключенном питании проверить соответствие контактов.

Текущая прошивка использует **PB8** для DATA DHT11. Штатные переключатели TS1 ведут DQ к **PA3 или PB10**, а не к PB8. Простое включение DS1820-переключателя не соединяет датчик с текущим входом программы.

Для текущей прошивки практический вариант через провода:

| Контакт модуля DHT11 | Подключение |
|---|---|
| GND / − | GND платы, можно взять GND TS1 |
| VCC / + | 3,3 В платы, можно взять VCC TS1, если модуль поддерживает питание 3,3 В |
| S / DATA / OUT | PB8 на портовом разъёме |

При таком варианте TS1 используется только как источник питания. DATA не обязана проходить через гнездо TS1. Подтяжка DATA к 3,3 В должна быть на модуле или внешняя 4,7–5,1 кОм. Если модулю требуется 5 В, применять питание по его паспорту и open-drain преобразователь уровней на линии DATA.

Если используется именно сигнальный контакт DQ TS1, соединения выполняются по назначению: модуль DATA → DQ TS1, а от DQ отдельная перемычка → PB8. Переключатели TS1 → PA3/PB10 в этом варианте выключены; штатная подтяжка DQ 1,5 кОм к 3,3 В уже присутствует. Перед прямой вставкой модуля обязательно проверить физический порядок его ножек и контактов TS1: без маркировки/фотографии ориентация не определена.

Для PB8 отключить нагрузку LED PORTB 8–15, внешнюю подтяжку вниз и коммутацию тачскрина DRIVEA/PB8. При этом группа PORTB 0–7 может оставаться включённой для LED PB6. После прошивки и Continue первые показания ожидаются после стартовой выдержки и опроса; обновление DHT11 — примерно раз в 2,2 секунды.

Источник TS1: [руководство EasyMx, стр. 34](https://www.tme.eu/Document/45b98ed55c7fba4e4a3c7ac66f771472/mikroe1099.pdf). Для конкретной ревизии переключатели выбирать по маркировке DS1820/PA3/PB10; нумерация блоков менялась.

Проверка встроенного потенциометра:

1. Выключить питание. Найти P1 секции ADC INPUT, а не P2 контраста дисплея.
2. Установить одну перемычку J8 на пару контактов с подписью PA4. Не соединять перемычкой два разных названия GPIO. Заводская цепь должна соединять движок P1 именно с PA4.
3. Отключить LED-нагрузку PA4, внешние подтяжки PA4 (среднее положение), другие источники на PA4. Убрать внешний провод, если он был подключён к PA0 или PA4. Не нажимать кнопку PA4 во время работы.
4. Прошить актуальный проект, где ADC1 настроен на IN4 / PA4, и нажать Continue после остановки в main.
5. Вращать P1 и смотреть строку ADC. Она должна изменяться воспроизводимо, без необходимости касаться выводов пальцем. При ADC<2048 LED PB6 выключен, при >=2048 в режиме PWM начинает светиться, затем яркость увеличивается.
6. Если P1 не влияет, измерить мультиметром напряжение PA4 относительно GND при вращении P1. Если напряжение не меняется — проверить P1/J8/контакт перемычки. Если меняется, а ADC нет — проверить выбранный канал и фактически загруженный ELF.

Изменения от касания пальцем — вероятный признак плавающего аналогового входа или плохого контакта; это не проверка работы P1. На PA4 должна приходить измеряемая величина от движка через J8. Для демонстрации не нужно касаться входа или замыкать его на питание проводом.

Если ADC изменяется, а LED не реагирует, проверить включение группы PORTB 0–7 / PORTB_L, штатный индикатор именно PB6 и отключение конфликтующей I²C-периферии. Сам порог сравнивается с необработанным коэффициентом делителя кодом ADC; изменение ADC_VREF_MV влияет только на отображение вольтов и не устраняет неподключённый вход.

## Подключение датчика и АЦП

| Сигнал | Вывод STM32 | Режим |
|---|---|---|
| DHT11 DATA/S | PB8 | Output Open Drain, начальное HIGH, No Pull |
| Встроенный P1 через J8 → PA4 | PA4 | ADC1_IN4, Analog |
| Управляемый светодиод | PB6 | TIM4_CH1, PWM, active HIGH |
| Общая земля | GND | Земля датчика и источника Vin |
| ST-LINK SWDIO / SWCLK | PA13 / PA14 | Serial Wire |

У вашего DHT11 три вывода на модуле: GND, VCC и S/DATA. Ориентироваться на маркировку, порядок не угадывать. На модуле обычно есть резистор подтяжки DATA к VCC; его наличие нужно проверить. Для модуля с паспортным питанием 3,3 В использовать VCC=3,3 В и подтяжку DATA к 3,3 В. Если модуль требует 5 В, применить двунаправленный open-drain преобразователь уровня, например BSS138, с подтяжками к 5 В и 3,3 В на соответствующих сторонах. Установить 100 нФ у питания датчика.

PB8 больше не служит зелёным светодиодом TrafficTimer: отключить LED-нагрузку и конфликтующую I²C-периферию от PB8. Для работы от P1 отключить другие источники от PA4. Если позже подключается внешний делитель, сначала снять J8 с PA4, чтобы не соединять два источника. Отключить ненужные внешние подтяжки. Не нажимать кнопки этих линий во время измерений.

## Штатный TFT на разъёме CN32

Подключение уже выполнено дорожками платы; внешние перемычки к экрану не нужны, если модуль установлен в штатный CN32 в правильной ориентации. Не подключать голый шлейф MI0283QT-8 напрямую по таблице CN32: она относится к плате-адаптеру дисплея EasyMx.

| Линия TFT | GPIO STM32 |
|---|---|
| D0…D7 | PE0…PE7 соответственно |
| RESET | PE8 |
| RD | PE10 |
| WR | PE11 |
| RS / D-C | PE12 |
| CS | PE15 |
| PWM подсветки | PE9 — программа его не использует |

Все сигналы TFT — Output Push Pull; RD/WR/CS/RESET/DC при запуске HIGH. GPIO уже настроены в IOC. Для выбранного режима полнояркостной подсветки включить переключатель **BCK_LIGHT**; PWM-переключатель оставить выключенным. По схеме v1.02/руководству это SW11.3, PWM — SW11.4, но ориентироваться прежде всего на подписи фактической платы: в других редакциях нумерация менялась. Отключить LED-нагрузки и подтяжки на используемых линиях PORTE.

На экране выводятся отдельными строками TEMP, HUM, ADC, U ADC (на PA4) и U IN (перед делителем), внизу статус DHT11. При включении — Sensor warm-up около 2,2 секунды. Датчик опрашивается раз в 2,2 секунды, АЦП усредняется по 16 отсчётам. При ошибке датчика старые показания заменяются прочерками. При насыщении АЦП отображается SATURATED. Цифры после запятой не означают соответствующую точность измерения.

Если TFT белый: проверить, что новая программа действительно прошита и после остановки main нажато Continue; включена подсветка; модуль установлен в CN32; выбран именно MI0283QT-8 / ILI9341. В старых комплектах EasyMx встречались HX8347D — этот драйвер предназначен для ILI9341, выбранного по вашей маркировке. Пустой экран сам по себе не доказывает ошибку DHT11.

## Внешний делитель: альтернативное подключение вместо P1

Для внешнего делителя снять J8 с PA4. Следующая схема относится к альтернативному внешнему источнику, а не к внутреннему соединению P1.

~~~text
Измеряемый Vin ── Rверх ──┬── PA4 (ADC1_IN4)
                         │
                        Rниз
                         │
                        GND
~~~

Опционально 10–100 нФ между PA4 и GND для медленно меняющегося напряжения. Сначала собрать делитель и измерить напряжение на PA4 мультиметром.

В App/Inc/monitor_config.h изменить DIVIDER_PROFILE и пересобрать:

| Значение макроса | Rверх | Rниз | Коэффициент | Пример рабочего Vin при PA4 ≤3,0 В |
|---|---:|---:|---:|---:|
| DIVIDER_DIRECT (по умолчанию) | 0 | — | 1 | 0…3 В |
| DIVIDER_10K_10K | 10 кОм | 10 кОм | 2 | 0…6 В |
| DIVIDER_30K_10K | 30 кОм | 10 кОм | 4 | 0…12 В |
| DIVIDER_100K_10K | 100 кОм | 10 кОм | 11 | 0…33 В |
| DIVIDER_CUSTOM | произвольно | произвольно | (Rверх+Rниз)/Rниз | 3,0 × коэффициент |

Для CUSTOM вписать фактические DIVIDER_TOP_OHM и DIVIDER_BOTTOM_OHM в соответствующей ветке. Резисторы должны выдерживать напряжение и мощность. DIRECT означает прямую подачу допустимого сигнала; резистор 10 кОм в конфигурации нужен только для математического коэффициента 1.

**Переключение профиля меняет только расчёт, не электрический диапазон. На PA4 допустимо 0…VREF+ (обычно 3,3 В), включая выбросы. Отрицательное напряжение недопустимо.** Значения 3,3/6,6/13,2/36,3 В — теоретические пределы для VREF+=3,3 В, без запаса на допуски. Поэтому в таблице приведён запас до 3,0 В на PA4.

Формулы:

~~~text
U_PA4 = ADC × VREF / 4095
Vin = U_PA4 × (Rверх + Rниз) / Rниз
~~~

Измеренное VREF+ относительно VSSA вписать в ADC_VREF_MV (милливольты). Код не измеряет VREF автоматически. Для точности нужны фактические номиналы резисторов и опорное напряжение. Высокое сопротивление источника, шум и допуски ограничивают точность.

## Клоки STM32CubeMX

В MCU Selector выбран STM32F107VCT7, корпус LQFP100. Стандартная MCU-карта EasyMx v7 поставлялась с STM32F107VCT6; периферия и разводка соответствуют STM32F107VC, суффикс температурного исполнения нужно сверить с маркировкой.

В Pinout & Configuration → System Core → RCC выбрать HSE = Crystal/Ceramic Resonator, HSE input = 25 MHz. Это именно кварц, не Bypass.

~~~text
HSE 25 MHz → PREDIV2 /5 → 5 MHz → PLL2 ×8 → 40 MHz
            → PREDIV1 /5 → 8 MHz → PLL ×9 → SYSCLK 72 MHz
~~~

| Параметр | Значение |
|---|---:|
| SYSCLK / AHB / HCLK | 72 МГц / делитель 1 |
| APB1 / PCLK1 | делитель 2 / 36 МГц |
| APB1 Timer Clock | 72 МГц (удвоение при делителе APB1≠1) |
| APB2 / PCLK2 | делитель 1 / 72 МГц |
| ADC clock | PCLK2 /6 = 12 МГц |
| TIM2 Prescaler | 71 → счётчик 1 МГц, шаг 1 мкс |
| TIM2 Counter Period | 65535 |
| TIM2 Clock Source | Internal Clock, без прерывания |
| TIM4 / CH1 / PB6 | PSC=71, ARR=999, PWM1, 1 кГц |
| Flash latency | 2 wait states |
| SysTick | 1 мс |

ADC1: IN4, один regular channel rank 1, software start, scan/continuous/discontinuous отключены, alignment right, sample time 239,5 cycles. DMA не требуется. SYS → Debug = Serial Wire. PB8 обязательно Open Drain. Настройки уже записаны в IOC.

USB OTG в пользовательской программе не включён: для загрузки через встроенный ROM DFU включать USB middleware в приложении не требуется. При добавлении USB-функций позже нужно отдельно настроить OTG и его источник 48 МГц. Дополнительные длительные обработчики прерываний могут нарушить программное считывание DHT11; текущий проект использует только короткий SysTick.

## Сборка и отладка в VS Code

Подключённое устройство: **0483:3748 ST-LINK/V2**. Это программатор, а не UART. Используется OpenOCD с настройками рабочего TrafficTimer: SWD 100 кГц, connect_assert_srst. Общая конфигурация — openocd.cfg.

1. Открыть именно эту папку в VS Code. BOOT0=0, коммутация SWD/NRST как в рабочем TrafficTimer.
2. Ctrl+Shift+B → Build STM32 — штатная сборка. Результат build/DHT11Monitor.elf.
3. Ctrl+Shift+D → **DHT11Monitor: ST-LINK USB (SWD)** → F5 — сборка, прошивка, остановка в main. Ещё F5 — Continue.
4. Для расширения STM32 for VSCode можно выбрать **Debug STM32**: Build STM и ELF из build/debug. Эта сборка также исправлена.
5. Для записи с немедленным запуском — Terminal → Run Task → flash-stlink. Все команды прошивки заменяют текущую программу на плате.

Не запускать одновременно два OpenOCD. Не требуется BOOT0=1 для ST-LINK. При breakpoint в процессе чтения DHT11 временные интервалы нарушаются: после Continue дождаться следующего опроса.

Из терминала:

~~~sh
python3 tools/project.py build
# Или сборка расширения:
make -j16 DEBUG=1 -f STM32Make.make
~~~

ARM GCC автоматически ищется в PATH или установленном STM32CubeIDE в /opt/st. На другой машине задаётся ARM_GCC_BIN. Для сборки расширения путь ARM_GCC_PATH хранится в .stm32env. Пути компилятора в VS Code также нужно обновить при переносе на другой ПК. HAL/CMSIS включены в репозиторий.

## CubeMX и повторная генерация

Открыть DHT11Monitor.ioc в CubeMX, изменить настройки и Generate Code. Затем python3 tools/project.py build возвращает вызовы приложения в USER CODE и включает App/Src. Для командной генерации есть задача regenerate; CubeMX требует графический сеанс DISPLAY/XAUTHORITY и пакет FW_F1 V1.8.7. tools/integrate.py удаляет известный лишний вызов включения PLL3 из шаблона CubeMX 6.18.1, как в рабочем TrafficTimer.

Для USB DEVICE ROM DFU оставлена задача flash-dfu, но она относится к другому USB-разъёму: PA11/PA12/VBUS, BOOT0=1, BOOT1=0 и RESET; затем после записи BOOT0=0 и RESET. Для уже обнаруженного ST-LINK этот режим не нужен. USB CDC/UART в пользовательском приложении не реализован.
